Abstract

This study investigates whether historical search-performance and content-related signals can help prioritize content that may be declining. The analysis uses 30,000 rows and 52 model features to compare a transparent baseline with Logistic Regression, Decision Tree, and Random Forest models. Models were evaluated using a client-holdout split, with Precision@50 used as the main prioritization metric. Random Forest achieved a Precision@50 of 0.74 compared with 0.24 for the baseline. The result is intended as directional decision support for human review rather than a guarantee of future content decline.

01

Introduction / Problem Statement

Content teams may have many pages that could require review, making it difficult to decide which pages should be examined first.

This project investigates whether historical search-performance and content signals can be used to prioritize potentially declining content.

Decision supported

Which content should be reviewed or refreshed first?

The goal is not to automatically change content. Instead, the model produces a ranked prioritization signal that can help a human reviewer decide where to investigate first.

03

Methodology

Feature Preparation

The pipeline cleaned the available data, prepared numeric and categorical features, and constructed the final feature vector. The resulting model input contained 52 features.

Models

Baseline

A transparent hand-written rule was used as the baseline that the learned models needed to beat.

Logistic Regression

A simple linear classification model used as one learned comparison point.

Decision Tree

A tree-based classifier used to capture non-linear relationships between features.

Random Forest

An ensemble of decision trees. It produced the strongest Precision@50 and was selected as the final model.

Validation Design

The pipeline used a client-holdout split. There were 27,675 training rows and 2,325 test rows.

Model Selection

Precision@50 was used as the primary model-selection metric because the practical objective is to prioritize a small ranked set of content for human review.

Leakage Checks

The feature preparation process was designed to keep target information out of the model features. Evaluation was performed on the held-out test set rather than on the training data.

05

Limitations

  • The model identifies patterns associated with the declining label; it does not prove that a page will decline in the future.
  • The evaluation is based on a client-holdout split and may not generalize to every website or search environment.
  • Feature importance describes model usefulness, not causation.
  • The target label reflects the project's available historical labeling process and may contain its own assumptions.
  • Model performance may vary when the data distribution or operating environment changes.
  • Recommendations require human review before implementation.
Honest framing

These results should be interpreted as measured and directional decision support. They should not be presented as a guarantee of future traffic, rankings, or content performance.

06

Ranked Recommendations

The model output is designed to help prioritize content for human review.

  1. Review high-risk pages first. Start with pages receiving the strongest decline-risk scores from the Random Forest model.
  2. Investigate weak search performance. Review pages showing weaker impressions, clicks, sessions, or search positions.
  3. Check older content. Review older pages and pages that have not been updated recently for outdated or less relevant information.
  4. Review engagement signals. Examine weaker engagement-related signals for possible content or user-experience issues.
  5. Use human review before action. The model should help decide what to investigate first. It should not automatically decide which content must be changed.

Conclusion

The analysis shows that a Random Forest model provided stronger top-ranked prioritization than the transparent baseline on the held-out evaluation set.

The main practical value is not automatic decision-making. Instead, the model can help a content team decide which pages deserve attention first.

The result should remain a human-reviewed, directional decision support signal rather than a guarantee of future content outcomes.
